# Usage accounting and `/usage`

agenthicc keeps provider usage in one session-scoped `UsageLedger`. The ledger
is opened with the same stable `session_id` and `conversation_id` as the
session conversation, and completed records are appended to the existing
conversation journal. The reactive TUI store is a projection of the ledger;
it is not an independent counter.

The default session total includes provider calls from direct turns, every
standard workflow phase, standard subagent workers, and manual or automatic
compaction. Each record carries its run, model, category, source, lifecycle,
cache-token fields, and cost provenance without storing prompts or responses.

`/usage` is local and immediate. It can be run while an agent, workflow, or
subagent is active and never calls the provider or adds a queued user message.
The beginning of its output remains compatible with existing consumers:

```text
Usage: input=123 output=45 total=168 cost=$0.6789 state=running queued=2 ...
```

Additional fields identify quality and durability, for example
`usage_status=complete`, `cost_status=estimated`, `calls=4`, and
`durability=durable`. Missing provider usage is shown as `unknown`/`partial`,
not as a fabricated zero. A provider-supplied zero remains a known zero.

## Workflows and generated workflows

`WorkflowConfig.usage_ledger` is populated by the session runner. The standard
`_run_agent_turn()` contract forwards it to every phase, so `code_plan`,
`create_workflow`, and custom workflows generated by `create_workflow` receive
accounting automatically when they use the standard phase runner. Custom code
that bypasses `_run_agent_turn()` and calls a provider directly must explicitly
use the ledger API or remain outside the standard accounting contract.

The workflow checkpoint stores workflow state and the conversation cursor; it
does not duplicate usage totals. On resume, journal records are folded before
the first new turn, so a new run extends the restored total rather than
overwriting it.

## Data quality and recovery

Chunk usage updates a provisional call. The per-call completion signal commits
that same call, and the cumulative run signal only records a missing residual.
Duplicate signals are idempotent. Cancellation preserves reported values and
marks the call cancelled; an empty provider response remains unavailable.

Legacy `conversation.jsonl` `tokens` events are read when no canonical usage
records exist. Canonical records take precedence when both formats are
present, preventing double counting. Corrupt trailing journal lines are
ignored after the durable prefix. If a journal write fails, the live snapshot
is retained but reports `durability=degraded`.
